WHAT 20260910120000_client_dedupe.sql DOES
------------------------------------------
  1. Adds generated columns name_key / email_key / phone_key to `clients`
     (normalized: lowercased/trimmed name, Ghana-folded phone e.g. 024...,
     +23324..., "024 123 4567" all compare equal).
  2. AUTO-MERGES existing clients that collide on an exact phone or email
     (survivor = earliest row; blanks back-filled from losers; every
     orders.client_id repointed; loser rows deleted), then creates:
       - unique index on phone_key  (partial, nulls allowed)
       - unique index on email_key  (partial, nulls allowed)
       - trigram GIN index on name_key
  3. Creates function find_client_candidates(name,email,phone,exclude_id,limit)
     used by every client-creating path (add-client form, edit-client,
     new-order "new customer", CSV bulk import).

Name-similarity is NEVER auto-merged — only exact phone/email collisions.
If you want to review even those by hand first, say so and the auto-merge
gets split into a separate report instead.

Verified locally: migration applies clean on Postgres 16, merge + repoint
works, matcher returns correct exact/fuzzy hits, unique indexes enforce.
